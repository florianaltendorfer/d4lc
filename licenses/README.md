This directory records everything this project derives from
[`josdemmers/Diablo4Companion`](https://github.com/josdemmers/Diablo4Companion):

- `slint-LICENSE` — the royalty-free Slint desktop license the UI stack is

  the settings screen satisfies its attribution clause). Identical to
  `LICENSES/LicenseRef-Slint-Royalty-free-2.0.md` in the Slint 1.18.1 crates
  (SHA-256
  `5167f5056e850419106ab6265efbdca7cba4d99c849d1445ca0bbf6a1e2315fe`).
- `tessdata-LICENSE` + `tessdata-provenance.md` — the Apache-2.0 license and
  origin record of the Tesseract language packs release bundles copy from the
  pinned upstream submodule (they originate from
  `tesseract-ocr/tessdata_fast`, not from Diablo4Companion).
- `license-provenance.json` — machine-readable record of upstream-derived
  files: source path, upstream commit, SHA256, destination.
- `upstream-file-manifest.json` — generated manifest of tracked upstream
  files; regenerate with
  `cargo run -q -p d4lc-cli -- upstream-manifest --write licenses/upstream-file-manifest.json`
  after an upstream submodule refresh.

Per-file hashes for imported assets additionally live in
`assets/provenance/asset-manifest.json`. The upstream sources themselves are
checked out as the `upstream/Diablo4Companion` submodule.

## Overlay text fonts

The overlay text path (`crates/d4lc-overlay-x11/src/text.rs`, shared by the
X11 and Wayland backends) rasterizes glyphs itself, so it needs a font.
Upstream draws all overlay text with `Consolas` bold (`OverlayHandler.cs:910`),
a Windows face that Linux hosts do not have. The port therefore applies one
deliberate selection rule, not a silent fallback:

1. `Consolas` in bold when the system font database has it;
2. otherwise the bundled `Inconsolata` Bold.

Nothing else is ever tried. The face in use is always named in the overlay
status limitation and in `TextRasterizer::assignment` (`Consolas Bold
(system)` or `Inconsolata Bold (bundled; Consolas Bold is not installed)`). A
face that cannot be loaded or parsed is reported and no text is drawn.

| Item | Origin | License | Ships as |
| --- | --- | --- | --- |
| `swash` 0.2 | crates.io (`swash`) | Apache-2.0 OR MIT | Rust dependency, no data |
| `fontdb` 0.24 (feature `fs` only) | crates.io (`fontdb`) | MIT | Rust dependency, no data |
| `Consolas` Bold | the host's system font database | Microsoft licence of the host's installation | **no font data is redistributed** |
| `Inconsolata` Bold 3.000 | [googlefonts/Inconsolata release v3.000](https://github.com/googlefonts/Inconsolata/releases/tag/v3.000), `fonts_ttf.zip` member `fonts/ttf/Inconsolata-Bold.ttf` | SIL Open Font License 1.1, Copyright 2006 The Inconsolata Project Authors | **embedded in the binary** (`include_bytes!`) |

The bundled font file is `crates/d4lc-overlay-x11/assets/fonts/Inconsolata-Bold.ttf`
(109728 bytes, SHA-256
`263faa57f6c00c43a04e77df7abd5cb5cd4aae9f93507002c1217e02641fc7e6`). Its
licence text, copied unchanged from the same release (`OFL.txt`, SHA-256
`5d362a6f8690517fd9a5573128a081d8bbbb2f92714cf00556e08fbbe9600426`), is
`licenses/Inconsolata-OFL.txt`. `licenses/bundled-fonts.json` records source
URLs and hashes for both.

Consequences for packaging:

- Every binary and release bundle that contains the overlay embeds the
  Inconsolata font, so it must carry the OFL text and the copyright line:
  `scripts/package_linux_release.sh` installs `Inconsolata-OFL.txt` and
  `bundled-fonts.json` into the bundle's `docs/`, and the release notes name
  the font. The font is used unmodified under its own name, so the OFL
  reserved-name clause does not apply; it is not sold on its own.
- The Consolas face is never redistributed. It is used only when the user's
  system already provides it.
- `cargo-deny` already allows the crate licenses (`deny.toml`, `[licenses]`);
  `swash` pulls `skrifa`, `yazi` and `zeno`, all MIT/Apache-2.0, and `fontdb`
  is used without the `memmap` and `fontconfig` features, so no new native
  library is linked. The OFL applies to the font file only, which is not a
  crate dependency.
- Release bundles additionally carry `docs/rust-dependency-notices.html`
  (generated by the release workflow with cargo-about from
  `packaging/about.toml`) and `docs/slint-LICENSE`; together they list every
  linked Rust crate and its license text.

## Wayland game-window observer protocol bindings

The Wayland game-window observer
(`crates/d4lc-app/src/game_window_observer/wayland.rs`, feature
`wayland-wm-backend`) observes the game window's focus, minimize, close and
geometry on KDE sessions through the
`org_kde_plasma_window_management` protocol. The client bindings come from
a crate dependency, not from a vendored protocol XML in this repository:

| Item | Origin | License | Ships as |
| --- | --- | --- | --- |
| `wayland-protocols-plasma` 0.3 | crates.io; generated bindings for KDE's [plasma-wayland-protocols](https://invent.kde.org/libraries/plasma-wayland-protocols) (the crate vendors that project's XML tree verbatim, including `plasma-window-management.xml`) | crate: MIT; the protocol XML definitions it generates from: LGPL-2.1-or-later | Rust dependency; generated binding code is compiled in, no protocol XML is redistributed by this repository |
| `wayland-client` 0.31 | crates.io (`wayland-client`) | MIT | Rust dependency, shared with the overlay backend stack |

Consequences for packaging:

- The LGPL-2.1-or-later material is the **protocol description XML** inside
  the upstream crate. What this repository compiles in is the binding code
  that crate generates from it at its release time; the exact protocol
  definition (interface versions, events) is pinned by the crate version in
  `Cargo.lock`. Neither the XML nor generated code is stored in this
  repository, so release bundles ship only compiled output, like any other
  dependency.
- The protocol choice is deliberate: KWin implements neither
  `zwlr_foreign_toplevel_management` nor focus state in
  `ext_foreign_toplevel_list`, and the plasma protocol is the only one that
  exposes another client's active/minimized/geometry state on KWin. Its
  description states only one client may bind it at a time — when another
  client (e.g. a panel) holds it, the observer reports the failure instead
  of claiming an observation it cannot run.
- `cargo-deny` sees only the MIT-licensed crate (`deny.toml`, `[licenses]`);
  the LGPL-licensed XML is data inside that crate's source distribution and
  is not scanned as a separate package.
